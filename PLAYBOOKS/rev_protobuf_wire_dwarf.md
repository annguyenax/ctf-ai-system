# Playbook — Rust/prost protobuf wire protocol via DWARF

## Preconditions

- Rust CLI binary that generates messages for a custom TCP protocol (not raw
  HTTP/JSON) — often built with `prost` (protobuf) + `argh`/`clap` (CLI args).
- Binary not necessarily stripped of debug info even if it looks "released".

## Minimal chain

1. `checksec` — check for `Debuginfo: Yes`. If present, this is a major shortcut.
2. `readelf --debug-dump=info <bin>` (huge output — grep/sed targeted ranges) to
   recover exact struct/enum layouts for the CLI arg types and the wire message
   types (oneof enums, field names).
3. `objdump -d` the `Message::encode_raw` functions and the oneof `encode`
   dispatch/jump table. The immediate value moved into the tag argument before
   each `prost::encoding::*::encode(tag, val, buf)` call is the literal protobuf
   field number. Wire type follows from which `encoding::*` function is called
   (`uint32`/varint vs `string`/`bytes`/message = length-delimited).
4. Determine framing (length prefixes, trailing bytes) by capturing the client's
   own generated output for each subcommand (`./client <cmd> ... > out.bin`) and
   diffing/hexdumping — do NOT guess framing purely from static analysis.
5. Validate framing against the LIVE server by replaying the client's own
   generated bytes first (should get sane responses) before hand-crafting new
   message types the CLI doesn't implement.
6. If a CLI subcommand panics with "not yet implemented" — that's the actual
   target; hand-craft its wire bytes yourself using the recovered schema.
7. If a well-formed, empty/default-valued field gets a generic error, suspect an
   anti-tampering "no canonical default encoding" check — pad with non-empty
   junk content in that field (content is often unvalidated, only its
   non-emptiness/non-defaultness matters).
8. Any oneof/field variant NOT exposed by any CLI subcommand is a strong signal
   for a chained/follow-up challenge — note it, don't ignore it.

## Success indicators

- Server responds with something other than a generic "bad encoding" family
  error (a real ack, data payload, or the flag itself).

## Fallbacks

- Use a plain Python `socket` script for all live probing — `nc`/`printf` over a
  remote/SSH shell can silently drop hex escapes or fail to show responses.
- Always use fresh connections per probe unless specifically testing
  session/multi-frame behavior — some servers are one-command-per-connection.

## Time-saving

DWARF + targeted disassembly of encode functions is faster and more precise than
full Ghidra decompilation for recovering a structured wire protocol.
