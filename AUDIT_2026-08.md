# ctf-ai-system audit - 2026-08

## Findings

1. Core rules were repeated across multiple entry files, while the actual loading policy did not prevent agents from reading too much context.
2. `SKILLS/SKILL.md` was a stale duplicate skill entry and could conflict with root `SKILL.md`.
3. There was no dedicated MISC or AI/ML route even though existing challenges use both.
4. Output requirements and `_TEMPLATE` disagreed; the template omitted timeline and reusable-pattern files.
5. Knowledge cards drifted in fields and path conventions. No validator enforced the contract.
6. A solved output could contain malformed `attempts.json`, missing evidence, and still be indexed as solved.
7. HexStrike guidance named conceptual configuration fields that the MCP tools do not uniformly expose. The client defaults to a 300-second request timeout while the guidance claimed 120 seconds.
8. Onboarding referenced stale localhost health URLs although the canonical server is on Kali at `192.168.77.138:8888`.
9. Raw exploit payloads for one Next.js challenge triggered Windows Defender, making both the playbook and card unreadable.
10. Static CVE details in category prompts risk becoming stale and can overfit future challenges.

## Changes in this upgrade

- Added a compact progressive-disclosure router and explicit solve state machine.
- Added MISC and AI/ML skills plus an embedding-only LoRA playbook.
- Added explicit candidate-versus-verified flag gates.
- Replaced conceptual HexStrike advice with real MCP tool names and health/degradation behavior.
- Added a consistent knowledge-card template and PowerShell validator.
- Expanded output templates and writeup pedagogy.
- Recommended removing the stale nested skill entry and sanitizing antivirus-triggering PoC documents.

## Current operational note

The HexStrike health endpoint at `http://192.168.77.138:8888/health` was unreachable during this audit. This should be recorded once per solve, then the agent should continue locally.
